---
description: Read-only correctness review of a branch, commit range, or existing pull request.
---

Review **$ARGUMENTS**. Read `${CLAUDE_PLUGIN_ROOT}/references/pr-policy.md` for risk depth and the reviewer contract.

Review the user-specified branch, `base..head` range, or PR number/URL; if omitted, review the current branch against its detected base. Resolve a PR's repository, base and head using `gh pr view`; fetch missing refs when necessary. Pin base, merge base and head SHAs, and inspect the committed diff and relevant callers, tests and project instructions. Report dirty worktree changes separately; do not silently include them in a committed-range review. For a release, also inspect the delivery range under the policy. If a range cannot be resolved, report the limitation rather than guessing.

Select intent and depth using the policy, or accept the caller's selection and evidence, escalating for identified risks. For standard/deep, spawn one fresh reviewer with the Agent tool (`subagent_type: general-purpose`, `model: sonnet`, not a fork), passing the pinned range and focused context under the policy. The user's invocation of this workflow, directly or through `create-pr` or `create-pr-and-fix-ci`, is their explicit request for that subagent: do not ask again or decline it as unrequested, unless project instructions say otherwise. If independent execution is unavailable, review in the current session and disclose the limitation. A standalone invocation may itself be the fresh reviewer when called in a separate session. Light reviews use the principal session. Do not duplicate a valid review supplied by the caller.

Review is read-only: do not edit files, push, or post comments. Verify findings against the code and report actionable correctness risks with severity (`important` or `minor`), provenance (`introduced` or `pre-existing`, per the policy), file/line references, and concrete failure scenarios. List `pre-existing` findings in a separate section; they do not block. Report the repository, pinned SHAs, intent/depth, confirmed and rejected findings with reasons, validation evidence consulted, and limitations. If no findings remain, say so. Recheck the relevant head/base before reporting and flag a changed state as stale.
